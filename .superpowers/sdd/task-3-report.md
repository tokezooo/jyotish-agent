## Algorithms and frozen-profile mapping

| Area | Deterministic implementation | Frozen choice / boundary |
|---|---|---|
| Chara karakas | Ranks Sun through Saturn for 7; adds Rahu for 8; converts sign degrees to one-arcsecond scores | Schemes 7/8; Rahu score `30° - degree`; exact ties raise `ExactKarakaTieError`; differences up to 60 arcseconds flag without reordering |
| Rasi drishti | Movable -> non-adjacent fixed; fixed -> non-adjacent movable; dual -> other dual signs | Pure zero-based sign geometry, symmetric invariant tested |
| Arudha | Inclusive sign count applied from house to lord and again from lord | Same/seventh projection moves to the tenth from the source house; A1-A12 plus AL=A1 and UL=A12 |
| Co-lords | Lexicographic maximum by rashi duration, then degree, then frozen fixed order | `greater_rashi_duration_then_degree_then_fixed_order`; Mars/Ketu and Saturn/Rahu are the only accepted pairs |
| Argala | 2/4/11 primary and 5 secondary contributions | Virodhargala pairs 12/10/3/9 respectively; returns contributors and obstructors without interpretation |
| Svamsa / karakamsa | D9 lagna sign / D9 sign occupied by AK | Accepts both hand-auditable mappings and actual immutable locked-session position tuples, including Rahu AK |
| Selected special lagnas | BL/HL/GL advance from solar longitude at one sign per 120/60/24 elapsed minutes | Pure modulo-360 geometry; no engine prediction API |
| Chara Dasha seed/progression | Male starts at lagna; female at seventh; odd-numbered sign seed progresses forward, even reverse | Required binary gender; odd-forward/even-reverse |
| Maha duration | Directional exclusive distance from period sign to resolved lord, minimum one | Equivalent to frozen inclusive-count-minus-one-minimum-one rule |
| Antardasha | Twelve equal microsecond-rounded partitions in the maha sign's direction, beginning with the next sign | Same direction from next sign |
| Time | Decimal arithmetic over 365.2425 days/year; ROUND_HALF_EVEN at microsecond; contiguous periods | Exact `[start,end)` membership and boundary tests |
| Birth confidence | Exact evaluates once; approximate evaluates earliest through latest inclusively at five-minute steps, max 120 minutes; unknown rejects | 1/3/25 sample boundaries and stable/unstable fact classification tested |
| Natal capture | One `_run_engine_session` call per permitted sample; callback returns immutable snapshot containing D1/D9 | No second engine path, no raw mutable chart access, no locked interface change |

## Independent fixture evidence

`tests/fixtures/jaimini_core_hand_checked_v1.json` is static and explicitly states that it is not
generated by `jyotish_agent.jaimini`. Expectations are small enough to audit by hand: degree ranks,
zero-based signs, and integer sign-distance tables. Tests only read the JSON; production code never
imports it.

Two expectation groups were corrected during the first GREEN attempt from independent arithmetic,
not copied from production output:

| Case | Initially written | Hand derivation | Correct expectation |
|---|---|---|---|
| Arudha, Gemini house (2), lord Virgo (5) | 8 | Inclusive distance is four signs; projecting four from Virgo gives Sagittarius (8), which is seventh from Gemini, so the frozen exception moves to the tenth from Gemini | Pisces (11) |
| Chara duration, Pisces (11) to lord Gemini (2) | 10 years | Pisces is an even-numbered sign and counts in reverse: Aquarius 1, Capricorn 2, Sagittarius 3, Scorpio 4, Libra 5, Virgo 6, Leo 7, Cancer 8, Gemini 9 | 9 years |

The same explicit rules were then applied across the complete 12-sign fixture arrays. The exact
timeline fixture is independently checked as one year after `2000-01-01T00:00:00Z` =
`2000-12-31T05:49:12Z`, and one twelfth = `2000-01-31T10:29:06Z`.

The packaged Phase-0 adjudication fixtures remain untouched and pending, as required by their
frozen source-review gate; this task does not falsely claim qualified human/source approval.

## Concerns / explicit limits

1. The frozen JSON profile explicitly serializes karaka, arudha, co-lord, Chara Dasha, and time
   choices, but does not serialize separate choice fields for rasi drishti, argala, svamsa,
   karakamsa, or BL/HL/GL. Those requested items use the conventional deterministic definitions
   stated in the table and tests; a future profile version should encode them if multiple schools
   are to be supported.
2. The frozen Jaimini input model requires binary gender semantically but has no gender field.
   Therefore the pure `chara_dasha` function requires gender explicitly; this task correctly avoids
   changing the public model/API, but a later facade task must resolve that contract gap.
3. Static fixture expectations are implementation-independent and hand-auditable, but are not
   claimed as qualified human/source-adjudicated. The packaged source map and adjudication fixtures
   intentionally remain `pending`; interpretation must continue to fail closed.
